# H0 — Contamination Probe

**Verdict: CLEAN.** The base model's pass-rate is not carried by surface-form
memorization. ADR-002 stands; training proceeds on MBPP+.

## The question

H0 is the project's load-bearing precondition. Every downstream claim (H1, H2)
is read off pass-rates, and those are only meaningful if they reflect the model
*generalizing* rather than *reciting* memorized MBPP+ solutions. MBPP is heavily
contaminated in models of this generation, so this has to be measured before any
training, not assumed.

**Operationalization.** If the model is reciting solutions keyed to the exact
prompt wording, a semantics-preserving perturbation of the prompt (rename the
function, paraphrase the docstring — same spec, different surface tokens) should
sharply drop the pass-rate. If the model is actually solving the problems, a
cosmetic rewrite should barely move it. So:

    drop = canonical_pass@1 - perturbed_pass@1

A large drop implicates memorization; a small drop is consistent with
generalization.

## Pre-registration (before the perturbed run)

The decision rule was committed to DECISIONS.md (ADR-002) and pushed *before* the
perturbed pass-rate existed, so the verdict is read off a fixed rule rather than
chosen after the fact:

| drop | verdict | action |
|---|---|---|
| <= 5 pp | clean | ADR-002 stands; train on MBPP+ |
| 5-15 pp | ambiguous | escalate to the full ~369 for a tighter estimate |
| >= 15 pp | contaminated | ADR-002 reverses; train on perturbed variants |

## Method

- **Sample.** A frozen 100-problem MBPP+ sample (seed 0) drawn from the 369-problem
  post-exclusion pool (ADR-007, ADR-009). Paired: the same 100 problems appear in
  both arms.
- **Instrument.** The perturbation generator (semantic-preserving function rename +
  docstring paraphrase). All 100 were validated — their perturbed canonical passes
  its own tests in the sandbox — in the instrument-readiness check (100/100 gated,
  0 no-ops). The Colab measurement regenerates them deterministically via the same
  seed and transforms.
- **Model / decoding.** Qwen2.5-Coder-1.5B base, zero-shot-plus-stub prompt,
  greedy (temperature 0). Identical across arms; the only variable that changes is
  whether the model sees the canonical or the perturbed prompt.
- **Grading.** Each completion's extracted function is run against the problem's
  own tests via the same `build_harness` used in training. (Graded via a stdin
  subprocess rather than the container sandbox, since Colab has no Docker; the
  harness source is identical, so grading semantics match.)
- **Statistics.** McNemar's test (exact binomial on the discordant pairs — the
  correct paired test) and a bootstrap CI on the paired per-problem difference.

## Result

```
canonical pass@1:   0.550 (55/100)
perturbed pass@1:   0.520 (52/100)
drop:               +3.0 pp
perturbed malformed: 0.010  (vs 0.020 canonical -- no format-failure confound)
```

**Paired 2x2:**

|              | pert PASS | pert FAIL |
|---|---|---|
| **canon PASS** | 48 | 7 |
| **canon FAIL** | 4 | 41 |

- **McNemar (exact, 11 discordant pairs): p = 0.549** — the drop is not
  distinguishable from zero.
- **Bootstrap 95% CI on the drop: [-3.0, +10.0] pp** — straddles zero.
- The discordant pairs split 7 (perturbation hurt) vs 4 (perturbation helped) —
  near-symmetric. A memorizing model would show a strongly *one-directional* drop
  (many canon-only passes, ~zero pert-only passes); the near-symmetry is the
  signature of sampling noise, not contamination.

## Verdict

drop = +3.0 pp, below the pre-registered 5 pp clean threshold, with a
non-significant McNemar test and a CI that includes zero. **CLEAN.** The
contamination precondition holds; ADR-002 is not reversed; training proceeds on
MBPP+. No escalation to the full 369 is warranted — 3 pp is not in the 5-15 pp
ambiguous band.

## Limitations (stated, not hidden)

- **Statistical power.** At n=100 and a ~0.54 base rate, the minimum detectable
  effect (alpha .05, power .80) is ~20 pp. This result rules out *gross*
  contamination; it cannot rule out a *mild* (<~20 pp) surface-memorization effect.
  That residual is acceptable because ADR-002's remedy is triggered only by gross
  contamination — a sub-threshold effect does not change the action (train on
  MBPP+). A larger paired run would tighten the CI but not move the verdict, so the
  GPU budget is reserved for Phase 4.
- **Perturbation scope.** The transforms are conservative by construction (function
  rename always applies; docstring paraphrase is a tight lead-in + synonym rewrite).
  A model memorizing at the *semantic* level rather than the surface level would be
  invisible to this probe. This is the known ceiling of any perturbation-based
  contamination check, and it is why H0 is a *precondition check*, not a proof of
  no memorization.
- **One perturbation per problem.** THESIS anticipated measuring perturbed pass-rate
  across several independent perturbations per problem. This run used one seeded
  perturbation per problem. Because each problem's perturbation is an independent
  draw, the bootstrap CI over problems already includes perturbation-to-perturbation
  variation; what is lost is the ability to separate that variation from
  problem-to-problem variation (a per-problem noise band). The verdict is read off
  the pre-registered point-estimate rule; the CI's upper end (+10 pp) is why the
  power limitation above is stated.
